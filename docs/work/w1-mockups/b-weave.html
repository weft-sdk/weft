In development

One interface for every way your services talk.

Call weft.http, weft.kafka or weft.ws from any of eleven languages. Weft runs the library you already use underneath, with types from one contract.

Read the design
Languages run vertically, transports across. Every crossing is one weft.* call. A gap is a combination the ecosystem does not support.

Before and after

      
The same endpoint, written twice.

      
Take an order over HTTP, publish it to Kafka and tell the customer's browser over a socket. Today that is three libraries, three setups and a request body typed as any.

    

    

      

        
server.ts


import express from "express"
import { createServer } from "node:http"
import { Kafka } from "kafkajs"
import { Server } from "socket.io"

const app = express()
app.use(express.json())
const server = createServer(app)
const io = new Server(server)

const kafka = new Kafka({ clientId: "orders", brokers: [process.env.KAFKA_BROKER] })
const producer = kafka.producer()
await producer.connect()

app.post("/orders", async (req, res) => {
  const order = await orders.create(req.body)   // req.body: any
  await producer.send({
    topic: "order.placed",
    messages: [{ key: order.id, value: JSON.stringify(order) }],
  })
  io.to(`order:${order.id}`).emit("order.status", "placed")
  res.json(order)
})
server.listen(3000)

      

      

        
Weftserver.ts


import { weft } from "./weft.gen"

weft.http.post("/orders", async ({ body }) => {   // body: CreateOrder
  const order = await orders.create(body)
  await weft.kafka.publish("order.placed", order)   // key comes from the contract
  weft.ws.to(`order:${order.id}`).emit("order.status", "placed")
  return order                                    // must be an Order
})

await weft.start()   // port, brokers and socket path come from weft.yaml

// Express, KafkaJS and Socket.io still run underneath.
// weft.kafka.client is the raw KafkaJS client when you need it.

      

    

  


  

    

      
How it works

      
Set up, write the contract, call.

    

    

      

        
1
Set up
weft init asks which transports you use and which library runs each one.


$ npx @weft-sdk/cli init
? Which communication do you use?
  HTTP, GraphQL, Kafka, WebSockets
? HTTP library?       Express
? GraphQL library?    Apollo
? Kafka library?      KafkaJS
? WebSocket library?  Socket.io
Installed @weft-sdk/core and 4 adapters
Wrote weft.yaml

      

      

        
2
Write the contract
Names and types, once, in a file every language reads.


// contracts/orders.weft
package orders @version("1.0.0")

type Order {
  id: uuid
  items: OrderItem[]
  total: Money
}

event order.placed: Order {
  key: id
}

      

      

        
3
Generate and call
weft gen writes typed code. Every name and payload is checked by your compiler.


$ weft gen

import { weft } from "./weft.gen"

weft.kafka.on("order.placed", async (order) => {
  // order: Order
  await payments.charge(order.id, order.total)
})

await weft.start()

      

    

  


  

    

      
Contracts

      
One event, six languages.

      
Each service gets the Order type in its own language, from the same .weft file. A Go consumer cannot drift from a TypeScript producer without the compiler saying so.

    

    

      

        
contracts/orders.weft


package orders @version("1.0.0")

enum Currency { EUR GBP USD }

type Money {
  amount: int            // minor units
  currency: Currency
}

type Order {
  id: uuid
  customerId: string
  items: OrderItem[]
  total: Money
  placedAt: timestamp
}

event order.placed: Order {
  key: id
}

Behaviour

      
The same rules on every transport.

      
Each library handles tracing, retries and errors its own way. Weft does them once, the same way, in every language.
