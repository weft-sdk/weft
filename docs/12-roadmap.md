## P3: Conformance suite and the Go package

Proves that two languages behave the same: a TypeScript service and a Go service talk through one contract and pass the same cases ([conformance](07-conformance.md), [shared behaviour](../spec/behaviour.md)). The Go module is in `go/` ([ADR 0022](decisions/0022-go-package-lives-in-go.md)); the harness is in `conformance/`. Each language ships a small **runner** that the harness drives over a JSON protocol ([spec/conformance-protocol.md](../spec/conformance-protocol.md)); the harness compiles the contracts to IR and hands the IR to the runner, so a runner needs no generated code. Nothing is published. The chain that decides the length is P3.1, P3.2, P3.3, P3.4, P3.8.

- [x] **P3.1** The harness and the TypeScript runner: the protocol, the case format, the harness (Rust, `conformance/harness`) that compiles contracts to IR and drives runners, a TypeScript runner, and the first cases: encoding and validation, where every language must give the same result and the same issues. Needs P2. Done when: `make conformance` runs the encoding and validation cases against the TypeScript runner, a case that the runtime gets wrong fails, and CI runs it. Done 2026-11-23. `weft-conformance` (a crate in the compiler workspace), the runner protocol ([spec/conformance-protocol.md](../spec/conformance-protocol.md)), the TypeScript runner and 171 cases in `conformance/`; the TypeScript runtime passes all of them. The harness is tested with fake runners that are wrong on purpose (one wrong answer fails exactly one case). CI: the `conformance` workflow.
- [x] **P3.2** The Go module and its contracts runtime: `go/` with CI, the IR types, validation, encoding and decoding, the eight error categories, and a Go runner. Needs P3.1. Done when: the Go runner passes every encoding and validation case, and the harness compares Go and TypeScript results case by case. Done 2026-11-23. `go/` (module `github.com/weft-sdk/weft/go`): the IR types, `Contracts` (`Decode`, `Encode`, `Validate`, JSON helpers), the eight error categories, and `weft-conformance-runner`. Go and TypeScript both pass all 171 cases, so they agree case by case. CI: the `go` workflow on three systems, and the `conformance` workflow runs both runners. Writing the Go version found a bug in the TypeScript one: when encoding, rules read the base64 text instead of the bytes, so a `bytes` `@length` rule was wrong (fixed, with a test). The wire format is documented once, in [spec/behaviour.md](../spec/behaviour.md).
- [x] **P3.3** Go lifecycle: `Weft` start and stop with a grace period, `weft.yaml` config, middleware, timeouts. Needs P3.2. Done when: the lifecycle and config cases of [spec/behaviour.md](../spec/behaviour.md#lifecycle) pass in Go. Done 2026-11-23. `Weft` (register, `Start`, `Stop`, `Dispatch`, `Track`), `ParseConfig` and `LoadConfig` (adds `gopkg.in/yaml.v3`), `Compose` middleware, `WithTimeout` and deadlines, ported from the TypeScript behaviour. Config is under conformance: the protocol has a `config` operation and 24 cases, which Go and TypeScript both pass (195 cases in all). The lifecycle (start order, draining, the grace period, a failed start) is tested in each language with the same scenarios, not through the protocol yet.
- [x] **P3.4** Go messaging: the adapter interface, CloudEvents envelopes, retries, dead letters, dedupe, an in-memory adapter, OpenTelemetry. Needs P3.3. Done when: the messaging cases (retry then succeed, dead letter, shutdown, envelope) pass in Go against the in-memory adapter. Done 2026-11-23. `Messaging`, `MessagingAdapter` with `Capabilities`, CloudEvents header helpers, `BackoffDelay`, `Dedupe`, `MemoryAdapter` and OpenTelemetry (new dependencies: `go.opentelemetry.io/otel` and friends, which raise the module to Go 1.26). The protocol gets a `messaging` scenario operation and 25 cases (retries with exact backoff, every error category, dead letters, the envelope, dedupe, shutdown), which Go and TypeScript both pass: 220 cases in all. Spans, trace context and metrics are tested in Go as in TypeScript.
- [ ] **P3.5** Go HTTP on `net/http`: serving the contract's routes, problem bodies, `to()` calls with retries and deadlines. Needs P3.3. Done when: the HTTP and error cases pass in Go, and a Go service and a TypeScript service call each other.
- [ ] **P3.6** Go Kafka on franz-go, tested against a real broker. Needs P3.4. Done when: it passes the messaging cases against Kafka, and a Go consumer reads what the TypeScript producer sent (and the reverse).
- [ ] **P3.7** `weft gen --lang go`: Go types, the embedded IR and the typed `weft` object, in the same spirit as the TypeScript output. Needs P3.5, P3.6. Done when: generated code compiles and `go vet`s, and wrong calls are compile errors.
- [ ] **P3.8** Cross-language cases and the compatibility table: every case that involves two services runs for each ordered pair of languages (TypeScript and Go), including trace continuation, and the results are written as a table. Needs P3.5, P3.6. Done when: the cross-language cases pass in CI, the table is written to a file, and nothing in the docs claims more than it shows.

Done when: a TypeScript service and a Go service talk through one contract over HTTP and Kafka and pass the cross-language cases in CI.
